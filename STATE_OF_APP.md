# State of the App — KuasaPrestij
> Last updated: 2026-07-10 (FK repoint + lean interactive schema + Shorts-feed redesign). Update this file after every architectural change.

---

## 1. What It Is

KuasaPrestij is an AI-powered adaptive assessment engine for Malaysian secondary school students (KSSM curriculum, Forms 4–5). A student picks a topic, gets a question, answers it, and the system adapts to their weaknesses. A teacher sees a live dashboard of class mastery and error patterns.

---

## 2. Tech Stack

| Layer | Technology |
|---|---|
| Backend API | FastAPI (`app/main.py`) |
| Agent pipeline | LangGraph (state machine, `agents/orchestrator.py`) |
| Primary LLM | Cerebras `llama-3.3-70b` (1M free tokens/day) |
| LLM fallback chain | OpenRouter → Groq → DeepSeek (paid, last resort) |
| Embeddings | `sentence-transformers/paraphrase-multilingual-mpnet-base-v2` (local, 768-dim) |
| Database | Supabase (Postgres + pgvector) |
| Storage | Supabase Storage (`media_bucket`) for TTS audio MP3s |
| TTS | `edge-tts` — `ms-MY-YasminNeural` / `en-US-JennyNeural` / `zh-CN-XiaoxiaoNeural` |
| Telemetry | `TraceMiddleware` + `log_span` → `agent_traces` table |
| Alerts | Telegram Bot API — daily digest + mastery-drop alerts |
| Frontend | React + TanStack Router (Vite). Live on Cloudflare/VPS; parallel instance on Cloud Run |
| Hosting | **Hybrid (2026-07-30):** compute on **GCP Cloud Run** (`asia-southeast1`), database stays on **Supabase**. Also still on VPS. See §8e |

## 3. Agent Pipeline

```
/start_session
       │
       ▼
 retriever_node          ← fetches DSKP syllabus context + student history from Supabase
       │
       ▼
 studio_node             ← Q1 only (answered_count = 0, effective_adaptive = False)
   │ bank HIT            → read anchor from topic_anchors (LLM does nothing)
   │ bank MISS           → LLM generates anchor question + mnemonic lyrics + diagram SVG
   │                       (TTS audio + diagram SVG generated in parallel, cached forever)
   │
   └─ OR ─► generator_node   ← Q2+ (answered_count ≥ 1, effective_adaptive = True)
                              → LLM generates fresh question at correct KBAT level
                                personalised to student's mistake history

/submit_answer
       │
       ▼
 evaluator_node          ← LLM evaluates answer, writes feedback, categorises error
       │
       ▼
 mastery_updater_node    ← rule-based: ±0.1/±0.05 to dskp_mastery score
```

### KBAT Sequence (Phase 4)
| Question # | KBAT Level | Bloom's | LLM Role |
|---|---|---|---|
| Q1 | Memahami | C2 | None (bank hit) or one-time seeding |
| Q2 | Mengaplikasi | C3 | Adaptive generation |
| Q3 | Menganalisis | C4 | Adaptive generation |
| Q4+ | Menilai | C5 | Adaptive generation |

## 4. LLM's Actual Runtime Role (post-caching)

| When triggered | Node | What the LLM does | Frequency |
|---|---|---|---|
| Q1, topic already seen | bank hit | **Nothing** | Every Q1 after first visit |
| Q1, new topic (first ever visit) | `studio_node` | Anchor question + mnemonic lyrics + diagram SVG | Once per topic, cached forever |
| Q2+ | `generator_node` | Personalised question at correct KBAT level | Every adaptive question |
| Every answer submission | `evaluator_node` | Correctness judgement + feedback + error category | Every `/submit_answer` |
| Teacher dashboard | `_generate_teacher_narrative` | 3–5 sentence class health summary | On `/teacher_insights` (cached 5 min) |
| Background | `remediation_planner` | Topic sequence plan per student | Triggered on mastery drop |

The LLM is no longer a content-delivery engine. It is a **personalisation + evaluation engine**. All static content is generated once and cached.

## 5. Caching Architecture (`topic_anchors` table)

Every topic × language × form_level combination gets one row that holds:

| Column | What | Generated by |
|---|---|---|
| `anchor_question` | C2 Memahami question (JSON) | `studio_node` (LLM, once) |
| `mnemonic_lyrics` | Rap/song lyrics for the mnemonic | `studio_node` (LLM, once) |
| `audio_url` | TTS MP3 URL in Supabase Storage | `studio_node` / `seed_audio.py` |
| `diagram_svg` | SVG diagram as background | `studio_node` (LLM, once) / `seed_diagrams.py` |
| `video_broll` | Pexels video URL (fallback only) | `studio_node` (Pexels API, skipped if diagram exists) |
| `interactive_content` | **Lean interactive blob** (going-forward format) | `studio_node` (`_build_interactive_blob`); backfilled from h5p_content |
| `h5p_content` | Legacy H5P blob JSON — **deprecating**, dual-written for rollback | Built in-memory from cached fields |
| `worked_example` | Step-by-step worked example | `seed_worked_examples.py` |
| `question_bank` | Pool of pre-generated questions | `seed_anchors.py` / `seed_spm_anchors.py` |

**Lean interactive schema (2026-07-10):** The frontend never ran a real H5P engine — `InteractiveVideoPlayer` hand-parsed the blob for ~8 fields. The lean `interactive_content` `{video_url, audio_url, audio_end_sec, question, options[], mcq_start_sec, drag?}` replaces it. `/start_session` returns `interactive` (prefers stored column, else converts legacy via `_h5p_to_lean`). Frontend prefers `interactive`, falls back to the legacy blob → existing rows work with no re-seed. `h5p_content` is still dual-written for one release, then can be dropped.

**Phase 5 rule:** If `diagram_svg` is present, `video_url = ""` → H5P blob has `files: []` → frontend auto-skips intro and renders SVG as full-bleed background. Pexels is never called.

## 8d. 2026-07-15 Changes — Essay marking robustness + invite-code fix

### Essay submit timeout → 5 min + marking countdown
Essay marking is a live LLM generation (band rubric + written feedback) that can take
minutes; the old 60 s client abort could kill it mid-marking.
- **`services/api.ts` `submitAnswer`** now takes a `questionType`; essays get a **300 s
  (5 min)** `AbortController` timeout (MCQ/short stay 60 s). nginx `proxy_read_timeout`
  is 600 s, so 5 min is safe. **Essays are never mock-graded** — on failure it throws
  (a mock "answer is C" verdict used to silently mark a real composition wrong).
- **`components/EssayMarkingCountdown.tsx`** (new): self-driving overlay showing time
  remaining before the 5-min timeout; amber alert state at ≤30 s. Wired into feed
  (`QuestionSlide`, `active={checking && !isMcq}`, + timeout toast) and card (`index.tsx`).
- **Feed essay input** switched from single-line `<Input>` to multi-line `<Textarea>`
  (`QuestionSlide.tsx`, essay only; Ctrl/Cmd+Enter submits, plain Enter = newline).

### Teacher feedback recorded on passing essays
`orchestrator.py::mastery_updater_node` — `event_logs.diagnostic_tag` now always records
the marker's `teacher_action_plan` (e.g. `[Insufficient Depth] Band A — 9/10 marks. …`),
not just "Mastery demonstrated" on a pass. Addresses critique §9 item 3 (marks now stored
for the teacher; still not surfaced to the *student* overlay — that remains open).

### Invite-code join fixed + Toaster mounted
`routes/__root.tsx`: capture `?invite=` into `localStorage` the instant it appears (was
dropped by the login redirect + email-confirmation round-trip), consume once a **student**
profile loads via `join_classroom_by_code` RPC, with toast feedback. Mounted `<Toaster />`
(previously never rendered, so *all* `toast()` calls were invisible app-wide).

### Deployment fragility — frontend runs `vite dev` in prod (known issue, 2026-07-15)
The student site is served by a **Vite dev server** (`kuasaprestij-frontend.service`,
`npm run dev` :3000), reachable at `http://<VPS-IP>:3000` (`VITE_APP_URL`). A
`kuasaprestij-frontend-pull.timer` used to `git pull` + `systemctl restart` **every 5 min**,
which dropped the Vite HMR socket and **full-reloaded every live browser** (resetting React
state → students bounced to the study-mode screen mid-essay, no warning). This was mis-read
as an "essay timeout." **Mitigation applied:** the 5-min pull timer is now **disabled**
(deploys are manual). Root fix deferred (B1): the app is **TanStack Start built for
Cloudflare Workers** (`.output/server/index.mjs` = Workers `fetch()` handler; a VPS
node-server build fails against the Lovable/CF config), so the correct production path is
`wrangler deploy` to Cloudflare, not a VPS build. Docker would only help as packaging, not
as a fix (dev server still reloads on restart). See WORKSPACE.md for the full trace.

## 9. Teacher & App User Critique (post Phase 1–5)

*Written from the perspective of a Form 4 teacher who has been using the app for 3 weeks with a class of 32 students.*

---

### What works well

**The KBAT progression (Phase 4) is pedagogically sound.** Starting at C2 and climbing to C5 mirrors how a good teacher scaffolds a lesson. Students who struggle at C3 are visible — their mastery stalls and the system flags them. This is exactly what I want.

**The mnemonic + diagram combo (Phases 3 + 5) reduces the blank-page problem.** Students who would normally stare at a question now have a visual anchor and an audio hook before the question appears. Anecdotally, time-on-task goes up.

**The evaluator feedback is specific.** Unlike a red X, it names the misconception. That's rare even in commercial platforms.

---

### What is broken or missing

#### 1. ~~Q1 is disconnected from Q2+~~ ✅ Fixed 2026-07-07
- Backend carries `diagram_svg` forward for Q2+ via a cheap `SELECT` after `generator_node` runs
- Frontend preserves `diagramSvg` state across questions; only clears on topic change
- Compact diagram panel shown for all non-H5P questions (no longer gated on `hasSeenIntro`)
- Level-up chip (emerald pill, auto-dismisses 2.5s) fires when `kbat_level` advances

#### 2. The session ends with no summary
After the 4th question (Menilai, C5), the session just... stops. There is no "you got 3/4 correct, your weakest area was X, here's what to study next" screen. Students close the tab with no closure. This is the single biggest retention risk.

**Fix needed:** A session summary screen that shows: questions answered, KBAT levels reached, mastery delta, and a "next topic" nudge.

#### 3. Short-answer and essay questions have no rubric visible to the student
The evaluator uses a rubric internally, but the student only sees a feedback string. For open-ended questions — especially for SPM preparation — students need to see the marking scheme. "Your answer is partially correct" is not enough.

**Fix needed:** Surface `marks_awarded / max_marks` + the expected answer points in the feedback overlay for short_answer and essay types.

#### 4. The diagnostic is not re-entrant
If a student starts a diagnostic session and closes the tab, they start from scratch next time. For a 20-topic diagnostic this is a significant UX failure. The backend has `diagnostic_progress` but the frontend doesn't resume from it.

**Fix needed:** On diagnostic start, check `/diagnostic_progress` and resume from the last unanswered topic.

#### 5. Teacher insights show class aggregates but no per-student drill-down in the UI
The `/teacher_insights` endpoint returns rich data including flagged students, misconception clusters, and a narrative. But the teacher UI only surfaces the aggregate. I cannot click on a flagged student and see their error history in one tap.

**Fix needed:** Flagged student cards with an expandable error log and a "generate remediation" button.

#### 6. The mnemonic lyrics are in the wrong register for Form 5
The rap lyrics work well for Form 4 concrete topics (forces, cells). For Form 5 abstract topics (electrochemistry, calculus), the lyrics feel forced and sometimes inaccurate because the LLM is optimising for rhyme over correctness. One student told me the Physics mnemonic said "electrons flow through the wire like water" which is the exact misconception I'm trying to fix.

**Fix needed:** Add a `content_review_flag` to `topic_anchors`; flag any mnemonic that contains known misconception keywords for that subject. Teacher can edit or suppress it.

#### 7. No offline / low-bandwidth mode
Malaysia's rural schools have patchy 4G. The app makes 3–5 network calls just to display Q1 (session start, TTS audio, diagram, H5P). On a slow connection this is a 5–8s white screen. There is no loading skeleton, no cached state, and no graceful degradation.

**Fix needed:** Cache the last session in `localStorage`. Show a skeleton card immediately. Load H5P content progressively (question text first, then media).

#### 8. The leaderboard incentivises speed over depth
The scoring system rewards completing more questions faster. Students learn to skip through MCQs quickly without engaging with the mnemonic or the diagram. The KBAT progression is the right idea but the points system works against it.

**Fix needed:** Weight points by KBAT level reached (C5 answer = 5× C2 answer) and penalise wrong answers more heavily at lower KBAT levels (you should not be guessing C2).

CREATE INDEX IF NOT EXISTS syllabus_embeddings_embedding_idx

### Summary verdict

The architecture is sophisticated and the LLM integration is efficient. The caching strategy is correct — the LLM is now only called when it genuinely adds value (evaluation, adaptation). The pedagogical scaffolding (mnemonic → diagram → KBAT sequence) is sound in theory.

The gap is in **continuity and closure**: the experience feels like separate components stitched together rather than a coherent learning journey. A student who finishes 4 questions has no idea what they learned, what they should study next, or whether they improved. Fix the session summary screen next — that single change has the highest impact on student engagement and retention.
